# 策略池热同步 — 策略调整自动推送引擎

## Context

当前系统存在一个痛点：在 Dashboard 策略中心调整策略池（启用/禁用策略、修改参数）后，引擎不会自动感知变化，需要手动重启引擎才能生效。虽然 `add_strategy()` / `remove_strategy()` 已有运行时动态增删能力，但没有一个自动检测机制来把策略池变更同步到运行中的引擎。

**目标**：用户在前端保存策略池后，引擎自动检测差异并执行 add/remove，无需重启。

---

## 设计

### 核心思路

在引擎的 `_tick()` 循环中（已有配置热重载逻辑附近），新增一个 **策略池同步** 步骤：

1. 每次 tick 调用 `_get_strategy_pool()` 读取当前策略池配置（来自共享内存的 RuntimeConfig）
2. 与 `self.strategies` 中的运行中策略列表做 diff
3. 对 `enabled=false` 或 `max_positions=0` 的策略 → 调用 `remove_strategy()`
4. 对池中有但 `self.strategies` 中没有的策略 → 调用 `add_strategy()`
5. 对 `max_positions` / `double_first` 变化的策略 → 更新实例属性

### 修改文件

| 文件 | 修改内容 |
|------|---------|
| `engine_standalone/main.py` | 新增 `_sync_strategy_pool()` 方法，在 `_tick()` 中调用 |

无需修改其他文件，因为：
- `RuntimeConfig` 已经是共享内存单例，API 写入后引擎立即可见
- `add_strategy()` / `remove_strategy()` 已存在且线程安全
- `_get_strategy_pool()` 已存在且每次读 RuntimeConfig 的 in-memory dict

### 详细实现

#### 新增方法 `TradingEngine._sync_strategy_pool()`

```python
def _sync_strategy_pool(self):
    """将 running strategy list 与 strategy_pool 配置同步（自动增删策略）"""
    pool = self._get_strategy_pool()
    if not pool:
        return

    with self._strategies_lock:
        current = {s.name: s for s in self.strategies}
        pool_names = set(pool.keys())

    # 1. 移除：池中标记为禁用或 max_positions=0 的策略
    for name, s in list(current.items()):
        cfg = pool.get(name)
        if cfg is None or not cfg.get("enabled", True) or cfg.get("max_positions", 1) == 0:
            if name in current:
                self.remove_strategy(name, close_positions=True)
                logger.info(f"[策略池同步] 已移除 {name}")

    # 2. 添加：池中启用但未在运行中的策略
    for name, cfg in pool.items():
        if not cfg.get("enabled", True) or cfg.get("max_positions", 1) == 0:
            continue
        if name not in current:
            self.add_strategy(name, cfg)
            logger.info(f"[策略池同步] 已添加 {name}")

    # 3. 更新：参数变更（max_positions / double_first）
    with self._strategies_lock:
        for name, s in current.items():
            cfg = pool.get(name)
            if cfg is None:
                continue
            if s.max_positions != cfg.get("max_positions", 1):
                s.max_positions = cfg.get("max_positions", 1)
                logger.info(f"[策略池同步] {name} max_positions → {s.max_positions}")
            if s.double_first != cfg.get("double_first", False):
                s.double_first = cfg.get("double_first", False)
                logger.info(f"[策略池同步] {name} double_first → {s.double_first}")
```

**注意事项**：
- `remove_strategy()` 已内部使用 `_strategies_lock`，所以外层 lock 需要释放后调用，否则死锁
- 实际上 `remove_strategy` / `add_strategy` 各自都拿 `_strategies_lock`，所以外层的 `with self._strategies_lock` 只能用于构建 `current` 快照，不能包裹 add/remove 调用
- 参数更新（`max_positions` / `double_first`）是轻量属性赋值，在 lock 内完成

#### 在 `_tick()` 中调用

在 `_tick()` 的 **配置热重载** 块之后（约 line 807），新增调用：

```python
# 策略池热同步：自动增删策略（无需重启）
self._sync_strategy_pool()
```

位置选择理由：
- 配置热重载之后：确保 settings.py 已 reload
- 数据同步之前：让新的策略能参与本轮数据同步
- 风控/交易逻辑之前：让策略状态先就绪

### 同步频率

每次 `_tick()` 都调用。`_sync_strategy_pool()` 内部通过 dict 比较，开销很小（O(n)），不需要额外的节流。

### 前端提示更新

`StrategyPool.vue:424` 当前提示"引擎将在下个 tick 生效"——这个提示仍然准确。可考虑改为"策略配置已同步，引擎自动识别变更"，但非必须。

## 验证

1. 启动引擎 + 后端
2. 打开 Dashboard → 策略中心
3. 禁用某个启用中的策略（如 `stoch_trend_m30`）→ 保存
4. 观察引擎日志：应出现 `[策略池同步] 已移除 stoch_trend_m30`
5. 重新启用该策略 → 保存
6. 观察引擎日志：应出现 `[策略池同步] 已添加 stoch_trend_m30`
7. 检查 API: `GET /api/engine/strategies` 返回的 running 列表应与策略池一致
8. 验证持仓清理：禁用时有持仓的策略应自动平仓
