# 策略文档编写规范 v2.0

> 本文档定义 `docs/strategies/*.md` 的编写标准。所有策略文档必须严格遵循此规范。
> CLAUDE.md 中仅引用此文件，不再嵌入模板正文。

---

## 1. 总体要求

- **文件名:** `docs/strategies/{策略类名}.md`，即策略类的 `name` 属性值，不能带版本号后缀
- **每次新建/修改策略，必须同步更新此文件**，否则 API 接口 `GET /api/strategies/{name}/logic` 会缺失对应内容
- **YAML frontmatter** 的 `name` 字段必须精确匹配策略类的 `name` 属性
- **末行必须为:** `数据源: 全部指标从 DataFactory TA-Lib 读取`
- 系统 API 从此文件读取并返回结构化 JSON 给前端展示，**所有表格格式必须与解析器兼容**

---

## 2. YAML Frontmatter 标准

```yaml
---
name: 策略类的 name 属性（必填，精确匹配）
magic: STRATEGY_MAGIC（必填，整数）
version: STRATEGY_VERSION（必填）
type: 策略类型（必填）    # 取值: 趋势 / 反转 / 突破 / 组合 / 评分 / ML / 其他
display: 系统显示名（必填）
desc: 一句话描述，系统 UI 展示用（必填）
---
```

**`type` 字段取值说明：**

| 类型 | 适用场景 | 示例 |
|:----|:--------|:----|
| `趋势` | 顺势而为，追涨杀跌 | stoch_trend_h1, timeprofit_ea |
| `反转` | 均值回归，超买超卖 | mfi_bb_m30, rsi_grading_m30 |
| `突破` | 关键位突破，价格区间突破 | h1_breakout |
| `组合` | 多策略调度，不同信号组合 | sanqing_original (4策略调度) |
| `评分` | 多因子评分系统 | entry_score_pro, multi_confluence_quant |
| `ML` | 机器学习模型 | gold_auto_research (共识投票) |
| `其他` | 以上均不适用 | — |

## 3. 文档正文结构

### 3.1 标准结构（所有策略通用）

```markdown
## 评分因子

### BUY（做多）
| # | 因子 | 得分 | 说明 |
|:-:|:----|:----:|:----|
| ① | 因子名 | +N | 详细说明 |
| ② | 因子名 | 必要条件 | 必备条件，不满足则不交易 |

### SELL（做空）
| # | 因子 | 得分 | 说明 |
|:-:|:----|:----:|:----|
| ① | 因子名 | +N | 详细说明 |

## 出场逻辑

| # | 条件 | 说明 |
|:-:|:----|:----|
| ① | 条件名 | 详细说明 |

## 特别规则

- 特殊规则1...
- 特殊规则2...
- 数据源: 全部指标从 DataFactory TA-Lib 读取
```

### 3.2 表格格式要求（API 解析器兼容）

| 表格 | 必须的列 | 说明 |
|:----|:--------|:----|
| BUY/SELL 因子表 | `# \| 因子 \| 得分 \| 说明` | 四列，表头必须精确。得分列支持 `+N`、`必要条件`、`—` |
| 出场逻辑表 | `# \| 条件 \| 说明` | 三列，表头必须精确 |
| 分隔线 | `\|:-:\|:----\|:----:\|:----\|` | 必须与列数对应 |

## 4. 策略类型专有模板

### 4.1 评分型模板（`type: 评分`）

多因子评分系统，每个因子独立打分，总分决定入场方向。

```markdown
---
name: entry_score_pro
magic: 661101
version: v1
type: 评分
display: 6因子入场评分系统
desc: 6因子加权评分，TH=3.5，分为止盈/止损两档出场
---

## 评分因子

### BUY（做多）
| # | 因子 | 得分 | 说明 |
|:-:|:----|:----:|:----|
| ① | ADX 趋势 | +1.0 | ADX>25 趋势市加1分 |
| ② | RSI 超卖 | +0.5 | RSI<30 超卖区加0.5分 |
| ③ | 价格位置 | +1.0 | 价格在20周期区间底部30%以内加1分 |
| ④ | 成交量确认 | +0.5 | 成交量>20周期均量1.5倍加0.5分 |

**判决规则：** 总分≥TH（默认3.5）产生对应方向信号。

### SELL（做空）
| # | 因子 | 得分 | 说明 |
|:-:|:----|:----:|:----|
| ① | ADX 趋势 | +1.0 | ADX>25 趋势市加1分 |
| ② | RSI 超买 | +0.5 | RSI>70 超买区加0.5分 |
| ③ | 价格位置 | +1.0 | 价格在20周期区间顶部30%以内加1分 |
| ④ | 成交量确认 | +0.5 | 成交量>20周期均量1.5倍加0.5分 |

## 出场逻辑

| # | 条件 | 说明 |
|:-:|:----|:----|
| ① | 硬止损 | 亏损超过 2.0 ATR |
| ② | 止盈档 1 | 首目标 2.0 ATR |
| ③ | 止盈档 2 | 次目标 3.5 ATR（仅ADX>25时启用） |

## 特别规则

- 评分总分≥TH 才出信号，TH 随 ADX 调整（ADX>25 时 TH=3.0，ADX≤25 时 TH=4.0）
- 出场加宽: ADX>25 时止损放宽至 2.5 ATR
- 数据源: 全部指标从 DataFactory TA-Lib 读取
```

### 4.2 条件型模板（`type: 趋势` / `type: 反转` / `type: 突破`）

非评分型，多个条件必须同时满足（AND 逻辑）才出信号。

```markdown
---
name: mfi_bb_m30
magic: 661001
version: v5
type: 反转
display: M30 MFI + 布林带均值回归
desc: MFI 80/20 + BB 触轨，均值回归
---

## 评分因子

### BUY（做多）
| # | 因子 | 得分 | 说明 |
|:-:|:----|:----:|:----|
| ① | BB 触下轨 | 必要条件 | 3 根 K 线内有 K 线低点 ≤ BB 下轨 |
| ② | MFI 超卖 | 必要条件 | 3 根 K 线内有 MFI ≤ 20 |
| — | 共振组合 | 1 | BB-LOW + MFI-OS 同时满足产生信号 |

**判决规则：** AND 逻辑——BB 触轨 + MFI 极端同时满足才触发。

### SELL（做空）
| # | 因子 | 得分 | 说明 |
|:-:|:----|:----:|:----|
| ① | BB 触上轨 | 必要条件 | 3 根 K 线内有 K 线高点 ≥ BB 上轨 |
| ② | MFI 超买 | 必要条件 | 3 根 K 线内有 MFI ≥ 80 |
| — | 共振组合 | 1 | BB-UP + MFI-OB 同时满足产生信号 |

## 出场逻辑

| # | 条件 | 说明 |
|:-:|:----|:----|
| ① | 顺势平仓 | 出现反向信号（另一极端 + 另一轨）时平仓 |
| ② | 逆势平仓 1 | 价格回到 BB 中轴 |
| ③ | 逆势平仓 2 | 价格走了开仓时 BB 宽度的一半 |

## 特别规则

- 容差 3 根 K 线：MFI 和 BB 触轨在 3 根 K 线内出现即可
- 数据源: 全部指标从 DataFactory TA-Lib 读取
```

### 4.3 多策略调度型模板（`type: 组合`）

多个子策略按优先级调度，每根 K 线只出一个信号。

```markdown
---
name: sanqing_original
magic: 880201
version: v1_original
type: 组合
display: Sanqing Original — 三清 M5 4策略调度器
desc: 原始 sanqing-ea 移植，M5 4策略优先级调度
---

## 原始出处

- **GitHub:** [caoruihua/sanqing-ea](https://github.com/caoruihua/sanqing-ea)
- **语言:** MQL4 (MT4) → Python 移植
- **作者:** caoruihua
- **说明:** 一个完整的 M5 4 策略调度器，核心文件为 `StrategySelector.mq4`，包含 4 个策略模块按优先级逐级判断，同一根 K 线只出一个信号。

## 策略架构

### 4 策略优先级调度

| 优先级 | 策略 | 说明 |
|:-----:|:----|:----|
| 1 (最高) | ExpansionFollow | 极端放量跟随：实体/ATR≥4.0 + 实体/中位数≥2.20 + 成交量/中位数≥1.9 + 实体/范围≥0.65 |
| 2 | Pullback | EMA回踩拒绝：EMA9>21 时价格回踩EMA9附近出现的下影线拒绝信号 |
| 3 | TrendContinuation | 趋势延续突破：EMA9>21 时收盘突破前高+0.2×ATR |
| 4 (最低) | PinbarReversal | PinBar反转：前置波动≥PinBar的3倍+影线≥2×实体+对侧影线≤0.5×实体 |

### 调度规则

- 从 ExpansionFollow → PinbarReversal 逐级检查，任一策略产生有效信号立即返回
- 同一根 M5 K 线只处理一次

## 评分因子

### BUY（做多）
| # | 因子 | 得分 | 说明 |
|:-:|:----|:----:|:----|
| ① | 任一子策略信号 | 1 | ExpansionFollow/Pullback/TrendContinuation/PinbarReversal 任一产生做多信号 |

### SELL（做空）
| # | 因子 | 得分 | 说明 |
|:-:|:----|:----:|:----|
| ① | 任一子策略信号 | 1 | ExpansionFollow/Pullback/TrendContinuation/PinbarReversal 任一产生做空信号 |

## 出场逻辑

| # | 条件 | 说明 |
|:-:|:----|:----|
| ① | 固定止损 | 1.2×ATR |
| ② | 固定止盈 | 2.0×ATR |
| ③ | 日风控 | 日盈利$50/日亏损$40锁定，次日重置 |

## 特别规则

- 低波动过滤: ATR<300points 或 ATR/Spread<3 时不出手
- 冷却期: 盈利平仓后 300 秒内同方向不再开仓
- 日风控锁定后所有交易暂停，到次日重置
- 数据源: 全部指标从 DataFactory TA-Lib 读取
```

### 4.4 移植策略补充说明

对于从外部移植的策略（如 GitHub / MQL5 社区），必须在 `## 评分因子` 上方添加 `## 原始出处` 模块：

```markdown
## 原始出处

- **GitHub:** [用户名/仓库名](https://github.com/用户名/仓库名)
- **语言:** MQL4/MQL5 → Python 移植
- **作者:** 原作者名
- **说明:** 简单描述原始策略的核心逻辑和特点
```

## 5. 快速参考（常见问题）

| 问题 | 答案 |
|:----|:-----|
| 文件名怎么定？ | `docs/strategies/{策略类name}.md`，无版本号后缀 |
| 评分型和非评分型的区别？ | 评分型：因子有得分权重，总分决定方向；非评分型：条件型 AND 逻辑，全部满足才出信号 |
| 条件型策略的因子怎么写？ | 在得分列写"必要条件"，额外加一行 `— \| 共振组合 \| 1 \| 说明` 表示条件全部满足 |
| 组合型策略的因子怎么写？ | 子策略都算同一个因子，得分=1，说明列写清楚子策略列表 |
| 移植策略要加什么？ | 在标准结构基础上，在 `## 评分因子` 上方加 `## 原始出处` 模块 |
| 出场逻辑表有几列？ | 3 列：`# \| 条件 \| 说明` |
| 入场因子表有几列？ | 4 列：`# \| 因子 \| 得分 \| 说明` |
| 标签颜色怎么配？ | 前端 `strategyColors.ts` 自动分配，按策略名匹配 |
| 不更新文档会怎样？ | API `GET /api/strategies/{name}/logic` 返回空，前端策略中心无显示 |
